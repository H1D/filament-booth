# Design

The booth turns a 3D print into a product photo in the browser. The user drops an STL or G-code, sets slicing, filament, lights and camera, sees a live preview, and presses PHOTO for a Cycles render that runs in the tab.

Two independent design sketches reached the same core shape: one saved document, one pure compile step, one frozen scene that every renderer reads. This file records that shape and the decisions made when the two were merged. The type sketch in `src/` is the contract. "A" and "B" below name the two sketches.

## Names

- `BoothDocument` (B): what the user edits and what is saved. Plain JSON.
- `Scene` (B's `FrozenScene`, A's `SceneIR`): the compiled, immutable result. Blender frame (Z up), metres, watts, linear colour. The only thing a renderer reads.
- `compileScene(doc, print)`: pure, runs in Node.

## Decisions

1. **Layout.** B's flat layout, with the rendering file split so no file passes about 500 lines:
   - `src/document.ts`, `src/presets.ts`, `src/print.ts` (+ `src/print/` worker internals), `src/scene.ts`, `src/booth.ts`
   - `src/film.ts`: AgX LUT loader, CPU tone map, PNG encode, quick preview of a partial frame. `public/lut/` holds the baked AgX
   - `src/photo/photo.ts`: the photo boundary (desk, run, engine interface). `src/photo/cycles.ts`, `src/photo/cycles-worker.ts`, `src/photo/raster.ts` are private to it
   - `src/viewport/viewport.ts`: the preview. `bead-material.ts`, `bake.ts`, `accumulate.ts`, `quality.ts` are private to it
   - `src/ui/`: React panels. `src/main.tsx`: wiring
   Import direction: document ← presets ← print ← scene ← film ← photo, viewport ← booth ← ui. Only `viewport/` and `photo/raster.ts` import three.js. Only `ui/` and `main.tsx` import React.
2. **Axis.** The app frame is Blender Z-up. The mesher emits Z-up metres. The viewport applies one root matrix `BLENDER_TO_VIEWER` to a group that holds part, sweep and lights (B). three.js keeps its default Y-up. A's `DEFAULT_UP = Z` is rejected.
3. **Camera.** Normal orbit camera with azimuth, elevation, distance and target (B). The turntable is a separate pose control. A's "no azimuth, drag spins the part" is rejected.
4. **Slicing settings live in the document** (A): `doc.slicing`. They apply when the print source is an STL. `PrintSource` for an STL carries no settings. A G-code reports its own settings on `SlicedPrint` with `settingsSource: 'file'`, and the panel shows them read-only. Slicer: the Muon3D engine (Orca in WebAssembly), one fresh worker per slice. Settings map to Orca keys: `layer_height`, `wall_loops`, `top_surface_pattern` (any of the eight patterns the engine accepts, listed once in `print/orca.ts`, which `document.ts` imports for its type and validator), `seam_position`, `outer_wall_line_width`, `inner_wall_line_width`, `top_shell_layers`, `enable_arc_fitting`.
5. **No revision counter in the saved document.** Remove `rev` from `BoothDocument`. `Booth` keeps a private revision number, and `Scene` carries it as `docRev` for stale-result checks.
6. **Edits.** `booth.update(mutate)` over a cloned draft (B) is the only write path. No reducer or intent union (A rejected). Edits that keep an invariant are named functions in `src/edits.ts` that return a mutator (`booth.update(applyLook("dark"))`, `booth.update(setFocal(85))`), so Booth has no second set of setter methods. `update` must keep untouched sections identical by reference, so clone only what the mutator touches, or compare sections after the mutation and reuse the old object when deep-equal.
7. **Change detection by section identity** (A). `Scene` has sections `part`, `lights`, `backdrop`, `world`, `camera`, `film`. `compileScene` takes the previous scene and returns the same section object when its inputs are unchanged. Renderers compare with `===`. Drop B's `hash` and `studioHash` strings.
8. **Lights in the scene are full frames** (A's `EmitterFrame`): `centre`, `xAxis`, `yAxis`, `normal`, `sizeM`, linear colour, `partOnly`. No renderer derives orientation from position and aim. Area lights keep `powerW` and `spreadRad`. Scrims keep top and bottom radiance. Shape is `rect` or `ellipse`.
9. **Floor cards are real scene elements.** B's `floorCards` stays in the document, and compiles to a `FloorCardRing` in the scene: an emissive disc on the floor that only glossy reflection rays see and that is light-linked to the part, so the backdrop's own glossy lobe never reflects it. The formula is the doc comment of `FloorCardRing`: azimuth runs as in `document.ts` (from -Y towards +X), radiance falls from `keyRadiance` on the key side to `farRadiance` opposite along the squared half cosine, and a radial fade takes it from full strength at `innerRadiusM` to zero at `outerRadiusM`. The preview bakes it as today. Cycles builds it as an emissive fan with camera, diffuse and shadow visibility off, and `render_scene.py` builds the same node tree. Delete "Cycles ignores it".
10. **Film settings are explicit** (A's `FilmIR`): width, height, samples, time limit in seconds (`timeLimitS`, 0 means none as in Blender, 300 by default; only the photo desk reads it, no engine does and native Blender ignores it), adaptive threshold, max bounces, glossy bounces, direct and indirect clamp, pixel filter width, transparent, denoise, view transform and look. Defaults come from one `FILM_DEFAULTS` constant. Its values were dumped from Blender 5.2.3 with `--factory-startup` (max bounces 12, diffuse 4, glossy 4, transmission 12, direct clamp 0, indirect clamp 10, Blackman-Harris at 1.5 px), then overridden where the reference stills differ (adaptive threshold 0.004, glossy bounces 8, look AgX Medium High Contrast).
11. **Output size** (A): `aspect` and `longEdgePx` in the document. Width and height are derived in `compileScene`. The camera section has no separate aspect field.
12. **Vertex data.** Keep one packed per-vertex word, as the existing worker does, defined once in `print.ts` as `BEAD_WORD` with `packBeadWord` and field descriptors (feature 2 bits, layer index, bead speed). It stays a Float32 attribute so the WebGL2 fallback works. B's separate `feature`, `layer`, `speedRel`, `layerRand` arrays are rejected: at 5 million vertices they cost about 60 MB more. The mesh also carries `tangent` (Int16, path direction) for anisotropy.
13. **Shading has one numeric source.** `compileScene` computes a `LayerTable` on the CPU: for every layer and every feature code, the final roughness before speed and mottle (per-feature base, gloss curve, per-layer sheen from a seeded random, heat gloss), plus a per-layer groove-flatten factor. Both renderers do the same small sum: `table[layer][feature] + speedRel * speedGain + mottle`, clamped to 0.05..1. The preview reads the table as a small data texture. The Cycles engine expands it to a per-vertex roughness attribute at upload. A's `Ops<N>` interface is rejected as more machinery than two formulas need.
14. **Tone map.** The photo is tone mapped with Blender 5.2.3's own AgX, not an approximation. The first version transcribed the Filament and three.js polynomial and measured 10 to 38/255 away from Blender, because Blender ships a different AgX, a 3D LUT in its OpenColorIO config. `tools/blender/bake_agx.py` bakes that config into `public/lut/`: Blender's 57^3 cube once (half float, shared by every look), and for each look a 49^3 warp of the shaper coordinate, indexed by Rec.709 log. One look loads about 1.8 MB (all six are 4.6 MB raw, 1.7 MB gzip). `film.ts` loads them with `loadAgx(look)` and its pure functions take the loaded `AgxData`. The preview samples the same files as 3D textures, with the recipe in the doc comment of `film.ts`: hardware trilinear for the warp, four nearest fetches (tetrahedral) for the cube. A test implements that recipe literally and checks it against the CPU path. Against native Blender the CPU path is within 0.7/255 on 429 probes in every look and within one 8-bit level on every pixel of a rendered frame (`tools/blender/agx_truth.py` writes the fixtures). The grid sizes come from `bake_agx.py study`; the reasons are in its docstring. This supersedes B's "AgX as data, a CPU and a shader implementation".
15. **Photo boundary** (A's shape, B's naming is fine): `desk.take(scene, partName)` returns a run with `progress` (state, fraction, latest image), `result: Promise<Photo>`, `cancel()` and `finishNow()` (stop sampling and develop what exists). The desk also ends sampling the same way when `film.timeLimitS` runs out (never before the first pass, so a photo is never empty), on a clock that starts when the first engine starts and carries over to a fallback engine. `Photo.stoppedBy` says what ended sampling: the sample target, the time limit or the user. One photo at a time. A new take cancels the one in flight and waits for its engine to stop before starting, so two runs never share the viewport. Engines implement `render(scene, onPass, signal) => Promise<RadianceFrame>` and a cheap `fits(scene)` check. Order: Cycles, then raster. A crash or out-of-memory in Cycles falls through to raster. Both engines return linear float frames and share `film.ts` for tone map and PNG.
16. **Print state** (B): `PrintState` union `empty | loading | ready | error`, with the last good part kept on show during an error or a re-slice. `PrintPipeline` hides slicing, parsing, exposed-wall detection, sweeping, caching and supersession. The lite mesh reuses the cached centreline; the worker sends it right after the full mesh.
17. **Plate face.** One constant `PLATE_EPS` in `print.ts`, tested on Z. Bed type comes from the document (`auto` reads the G-code's bed).
18. **Branded unit types** (B) stay in `document.ts`.
19. **Parity tooling.** `exportScene(scene)` in `scene.ts` is the one writer of the scene file: the JSON, and next to it the list of buffers by dotted path (`part.mesh.position`) with their element type. The caller writes each as `<path>.bin`. `tools/blender/render_scene.py` reads that and rebuilds the scene in native Blender 5.2.3. `tools/compare` reports per-pixel statistics between that and a browser photo.

20. **HDR images.** `presets.ts` holds the one table from `hdrId` to a file under `public/hdr/`. Both renderers load through it.
21. **A preset is copied, never referenced.** Applying a filament preset or a look copies its values into the document and records where from (`filament.presetId`, `lookBase`). Editing the copy leaves that record alone. `Booth.filamentModified` and `Booth.lookModified` compare the copy with the preset on every read, so editing a field back to the preset's value clears the mark, and Reset applies the recorded preset again. `presetId` is null only for a document that names no preset, which the Filament panel shows as Custom. Each filament preset carries `calibrated`: false for the two whose numbers are estimates (PLA Basic, PLA Silk), which the panel marks "estimate".

## How the merge was judged

A third model scored both sketches against six criteria without seeing my scores. It rated A higher on one definition per setting, Cycles parity and boundary depth (23 against 20 in total), and B higher on porting cost and reader load. It recommended A as the base with three grafts from B: the print source union, the root matrix, and a camera azimuth separate from the turntable. The merged design above already takes A's scene (explicit film, full light frames, real floor cards, one backdrop mesh) and those three grafts. It keeps B's flat file layout, which is the one point where I went against the judge's base, on reader load. Its red flag on B's `Booth` (generic `update` next to setter methods, two ways to do one task) led to decision 6.

## Tradeoffs accepted

- AgX exists as baked files with two small readers, CPU and shader, held together by a test that runs the shader recipe against the CPU path. It costs about 1.8 MB per look on first use, and the shader must do a tetrahedral fetch for the cube, because trilinear on it is up to 13.8/255 off. The alternative, one LUT per look on its own grid, measured 12 to 39/255 off at 49^3 because the cube clips to the display gamut.
- The raster photo engine borrows the live viewport, so the preview pauses during a raster photo. The alternative was a second offscreen copy of the scene on the GPU.
- The gloss slider is a new curve over each preset's recipe. The old viewer blended two calibrated finishes. Each preset at its default gloss still reproduces its calibrated numbers.
- `PlateFace.roughUnresolved` is a preview-only value that lives in the scene.

## Proven facts the design relies on

- Cycles 5.2 CPU kernel in WebAssembly renders 10 million triangles at 1280x720, 64 samples, in 24 s plus 7.7 s of BVH build, with 1.95 GB peak memory, on 16 threads. 
- The Muon3D slicer engine slices the 180 mm LEKV2 part in 12.7 s in a worker and matches native Orca filament length within 0.5 percent. Use one fresh worker per slice, because reusing one ran out of memory.
